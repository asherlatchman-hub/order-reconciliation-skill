    Why this is worth automating

    When orders are sold on one system and fulfilled on another, the two records drift apart. Orders get dropped, quantities are keyed wrong, rows are exported twice, and ID formats don't quite match.

    Checking them by hand means filtering two spreadsheets side by side, which is slow and error-prone, and it has to be done again every day or week. It's the kind of repetitive task a well-defined AI workflow handles well.

    Because it's a skill rather than a one-off prompt, the process lives in a file. Anyone on the team can upload two exports and get the same checks and the same report layout every time, without explaining the process again.

    How the skill works

    1. Identify the filesWorks out which export is the seller's and which is the warehouse's from file and column names, and asks once if it's unclear.
    2. Find the columnsRecognises common names automatically (Order ID, order_no, Ref; SKU, product_code; Quantity, qty_shipped), with overrides for unusual exports.
    3. Clean and matchTrims and upper-cases IDs so gn-10401 matches GN-10401, then matches on order ID + SKU, since one order can hold several products.
    4. Classify exceptionsMissing on either side, quantity differences, duplicates within a file, and data that can't be read.
    5. Sanity-checkIf the match rate is very low, Claude checks for a wrong column or an ID-format difference before reporting.
    6. Deliver the reportA formatted Excel file with a summary tab and one tab per exception type, plus a short chat summary that names the orders to chase first.

    Three design decisions

    Match on order ID + SKU, not ID aloneAn order with a T-shirt and a mug is two lines. Matching on ID alone would hide a missing mug.
    Sum duplicates before comparing quantitiesA repeated row shouldn't count as both a duplicate and a separate quantity problem, so the skill links them with a note.
    Unreadable rows go to Data QualityA quantity typed as "two" is a data-entry fault to fix at source, not a missing order, so it isn't reported as one.

    What's inside the skill

    SKILL.md tells Claude when to use the skill, the six-step workflow, how to check its own result and how to present findings.

    reconcile.py is a deterministic Python script (pandas + openpyxl) that does the matching and builds the report. The logic lives in code rather than in the prompt, so the same inputs always give the same output, and the AI part handles the judgement: reading the files, catching odd formats and explaining the results.

    It works with CSV or Excel files of any size, prints a JSON summary for Claude to explain, and writes an Excel report.
